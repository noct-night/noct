# 19hz

## The title is the line-up

19hz rows are `Title @ Venue (City)` and nothing else, so the adapter reported **0 line-ups out of 550
listings** — and outside New York 19hz is the dominant source. But the artists are in the title:
"Minimal Madness Ft. Zack Darza", "Niteharts: Isoxo, Jane Remover, Frost Children".

`src/lib/lineup.ts` reads them, precision over recall, because these names become rows in `artist` and feed
recommendations — a wrong split is worse than a missing one:

- Only strong markers count: `feat.` / `ft.` / `with` / `w/`, or a colon **followed by a list**. A single name
  after a colon stays a title, which is what keeps "Pilsen Stand-Up Presents: Comedy Showcase En Tu Idioma"
  from becoming an artist.
- Separators are 19hz's own: `,` `|` `*` `+` `&` `and` `/` and a spaced dash.
- `b2b` is left joined — one slot on the bill — because `parse_lineup_item()` splits it downstream, along with
  `(live)` and country suffixes.

Two bugs it shipped with, both now covered by tests:

1. **`\m` is PostgreSQL, not JavaScript.** The "event furniture" filter was written `/\m(party|rsvp|…)\M/`,
   which in JS is a literal `m` … `M` and matched nothing. `House Dance Party` and `Rsvp` reached the artist
   table before it became `\b`.
2. **A colon is sometimes part of the name.** `re:ni`, `Blu:sh`, `BLOND:ISH` and `19:26` are all real artists,
   so a prefix is stripped only when the colon is followed by a space — `Montecito 2026: Chainsmokers`.

Result: 19hz listings with a line-up 0 → 122, and event line-up coverage Chicago 43.2% → 49.2%,
Los Angeles 29.0% → 40.3%. The three artists the first, buggy run invented were deleted.
